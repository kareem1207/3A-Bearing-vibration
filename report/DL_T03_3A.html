1. Problem understanding

Breakdowns are rare, so a warning system must learn normal behaviour only and flag departures. The targets pull against each other: recall ≥ 0.85 on fault readings pushes the alarm threshold down; fewer than 2 false alarms per 24 h pushes it up; detection must come within 3 readings (the task's rule for data sampled slower than once a minute, here 10 minutes); no labelled fault may be used for training. A missed fault costs Rs 4 lakh and a false alarm Rs 2,000, a 200:1 ratio. Constraints I identified: only an unsupervised model is allowed; fault onset is not labelled in the real data, so any labels are an assumption; with one fault per run, test statistics rest on few events (3 test faults here).

2. Data preparation and exploratory analysis

Simulator (src/imsae/simulate.py): 8 run-to-failure runs × 4 bearings (700 snapshots each, 20480 samples, 4.9 days). Healthy bearings: noise, shaft harmonics at 33.3 Hz, a 6% daily amplitude cycle and benign transient bursts (≈1.7 per day) that imitate faults. One bearing per run develops an outer-race defect: impulses at 236.4 Hz ringing a 3.5 kHz resonance, amplitude 0.25σ at onset growing 40×. Split by run: 3 train, 2 validation, 3 test (seed-fixed). Features: per bearing 11 numbers per snapshot (log RMS, kurtosis, crest factor, 8 band log-powers). Each series is standardised with its own first 40% (assumed healthy; no labels). Training uses only that prefix (last 20% of it for early stopping). Validation runs choose thresholds; test runs give every reported number. Class balance: about 5–10% of readings are faulty. Fig. 2 shows the key EDA finding: the error of a healthy-trained model stays flat until well after the labelled onset.

3. Models and experiments

All are Keras autoencoders trained on healthy readings (Adam 1e-3, batch 32, ≤100 epochs, early stopping, 3 seeds 0–2). Score = reconstruction MSE of the newest reading. dense_wide: 11→64→11→64→11 (bottleneck = input). dense_narrow: bottleneck 8. dense_dae_sparse: bottleneck 16, input noise 0.2, L1 activity penalty 1e-3 (noise robustness and sparsity). lstm_dae (my "improved" model): LSTM encoder/decoder over a causal window of T=6 readings, bottleneck 8, input noise 0.1. The alarm fires when the score exceeds a threshold for m consecutive readings (m ∈ (1, 2, 3) and the threshold are chosen on validation data only). Two thresholds are compared: best reading-level F1, and minimum total cost (Rs 4 lakh per missed fault + Rs 2,000 per false alarm episode).

Cost model change (disclosed). My first version counted an alarm later than 3 readings as a miss. Every model then scored "missed", so "never alarm" became cheapest, which is meaningless. I changed it after seeing those first results: a fault is missed only if never alarmed before the run ends; timeliness is reported separately as "in time" (alarm within 3 readings). All tables use the corrected model.

5. Answers to the report questions

Q1. Why can an autoencoder with a bottleneck as wide as its input fail? With no compression a network with a hidden layer wider than the input can represent the identity map: capacity exceeds what the healthy data needs, so the training error becomes tiny (0.0002 versus 0.0098 at width 8 and 0.096 at width 2) and it also reconstructs mildly abnormal inputs well; this is the overfitting/low-bias end of the capacity curve, and the model has learned nothing about what normal looks like. A narrow bottleneck forces the network to keep only the structure shared by healthy data, so deviations from it cost error (the underfitting end appears at width 2, where even healthy error rises to 0.105). Evidence from my runs: AUC is 0.825 for the input-width bottleneck versus 0.876 at width 4 and 0.853 at 8 (Table 3). The gap is modest (about 1–2 seed standard deviations of the wide model, 0.02) and AUC is not monotone, so this supports but does not prove the argument.

Q2. Did the improved model beat the dense baseline? No. lstm_dae reaches AUC 0.831 ± 0.002 versus 0.853 ± 0.004 for dense_narrow, and the T ablation (T = 1, 3, 6, 12 → AUC 0.853, 0.865, 0.831, 0.829) shows no gain from longer context. Reasons I can support: each reading's 11 features already summarise a full second of vibration, and in this simulator the fault is stationary within a reading and grows smoothly, so what a recurrent model adds (temporal dependence between readings) carries little extra signal; the LSTM has more parameters yet the same 700-reading healthy training set, and it never triggered early stopping before the 100-epoch cap, so it may be under-trained, which I did not test. The best AUC came from the denoising, sparse dense model (0.866 ± 0.007), a small gain (≈ 2 standard deviations) from noise robustness and sparsity. On real IMS data temporal context may matter more; I cannot say.

Q3. Which threshold, given Rs 4 lakh per miss and Rs 2,000 per false alarm? Break-even is 200 false alarms per missed fault, so one expects the cost-optimal threshold to sit below the best-F1 one. Here it sits far above it (7.29 versus 0.046), because the simulated defect eventually grows so large that even a high threshold catches every fault before the run ends with zero false alarms (Rs 0 on the test runs versus Rs 112,000 for best-F1). The cost model, however, only counts breakdowns and false alarms; it ignores how late the warning comes. The min-cost threshold alarms on average 108 readings (≈ 18 h) after onset, the best-F1 one 45 readings (≈ 7.5 h). Because maintenance needs lead time I recommend the best-F1 threshold (error ≈ 0.046, m = 1): about one false alarm a day (inside the limit) and warning ≈ 10 h earlier, for roughly Rs 2,000 a day. Forcing recall to 0.85 needs ≈ 33 false alarms a day (Rs 66,000 a day), far outside the limit; the task's recall and false-alarm targets cannot both be met on this data.

6. Limitations and next steps

(i) Simulated data: absolute numbers are properties of my simulator (onset amplitude 0.25σ, 40× growth). A sensitivity run over the onset amplitude (AUC, Table 4) shows the picture depends strongly on it and that the model ranking is stable but small. Real IMS has no onset labels, load changes and sensor drift. (ii) Only 3 test faults and 3 seeds: differences of 0.01–0.03 AUC are within noise. (iii) The "in time" target is unattainable when the labelled onset is below the noise floor; a defensible onset label (for example from RMS or kurtosis trends) is needed for real data. (iv) The cost model changed after first results (section 3). (v) With more time: run on real IMS with literature onset labels, per-bearing thresholds, trend (CUSUM) alarms on the score, and train the LSTM longer.
